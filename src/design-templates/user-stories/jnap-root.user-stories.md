# JNAP Root User Stories

Status: active

These stories define the user intent behind Justin's root site and the reusable personal PR template workflow. JSON remains the source of truth at `src/design-templates/user-stories/jnap-root.user-stories.json`; this Markdown file is the readable review copy.

## Personas

- **Recruiter or hiring manager**: Needs a fast trust read and direct paths to resume, proof, and contact.
- **Potential collaborator**: Wants to understand what Justin makes, how he thinks, and where deeper work lives.
- **Personal visitor**: Wants a normal, curated human read without private material being exposed.
- **Client or small business prospect**: Wants evidence that the template system is organized, tasteful, and adaptable.
- **Template operator**: Uses the platform to turn a design direction into governed, agent-readable work.

## Stories

### Recruiter: Five-Second Read

As a recruiter, I want to understand the person and reach resume or proof in a few seconds so that I can decide whether to keep evaluating.

Success looks like identity plus professional exits in the first mobile viewport, no long pitch copy, and route labels that remain stable.

### Collaborator: Deeper Work

As a collaborator, I want a quick sense of projects, docs, and thinking so that I can find the right deeper surface to explore.

Success looks like docs and code exits being findable without category explanations, plus future project modules that can be added without rewriting shared content.

### Personal Visitor: Curated Human Read

As a personal visitor, I want the site to feel like a real person with taste and boundaries so that I trust the public identity without seeing private life.

Success looks like public-reviewed personal texture, normal human voice, and social routes that support the person without dominating the page.

### Client Prospect: Template Trust

As a client or small business prospect, I want to see a tasteful, flexible template system so that I can imagine adapting it to my own public identity.

Success looks like a clear one-pager, full candidate templates instead of minor tweaks, and template selection without canonical content changes.

### Operator: Governed Build

As a template operator, I want agents to read contracts, sources, stories, objects, and tokens before building so that autonomous slices remain governed.

Success looks like validation failing on missing source IDs, build plans tied to approved inputs, and inactive previews before activation.
